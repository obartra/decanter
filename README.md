# Decanter

A water sorting puzzle that runs entirely offline. Pour between bottles until
each one holds a single colour. No servers, no network calls, no analytics.
Fonts, icons, the one sound that is a recording, and the puzzle solver all ship
with the app.


## Quick start

```sh
npm run check     # lint, build, tests, size budget, dead code
npm run serve     # build and serve dist/ at http://localhost:8080
npm run pars      # recompute the par table (only after changing levels or the solver)
```

Open the local address and use the Install button, or your browser's install
option, to add it to a home screen or dock.

## The other games

Three of them now, each a page of its own built from its own sources by the same
build, sharing the fonts and the palette and nothing else. None is wired into the
graded hundred and twenty levels except the bubble game, whose boards are two per
chapter.

| | |
| --- | --- |
| `/bubble/` | a bubble shooter. **No par and it cannot have one** — the next bubble is dealt at random, so the board is not perfect information and there is nothing to search. A run is a fixed 35 shots with a row arriving every 4, graded on how far through it got: two bars are shot counts and the third is for finishing, by surviving the run or emptying the board. |
| `/measure/` | vessels of unequal capacity, the largest full. Pour between them until one holds exactly the target; there is no tap and no drain. Par is an exact breadth-first search. |
| `/casks/` | casks on a cellar floor that slide only along their own length. Get the gilt one to the door. Par is exact, and the boards are generated **backwards** — sliding is reversible, so one sweep of a layout's reachable component finds the start provably furthest from the door. |

`npm run bubble:survival`, `npm run measure:field` and `npm run casks:field`
re-measure each of them offline.

### Grading a game with no par

The bubble game's bars come from measured pass rates rather than from percentiles
of a perfect bot, which is the mistake the first version made. A bot's tenth
percentile is not a person's, and the bars read off one sat where a real player
cleared the first star — the one that opens the next level — barely half the
time. So the shot-chooser the hint button uses is given a miss rate, and the bars
have to hold across a range of them while staying above a player who is not
choosing at all.

What counts as a miss matters as much as how often it happens. A slip is the
bubble going into some other reachable cell, not the shot going off at a random
angle: a random angle buries itself in the first thing it meets and is a far
worse player than any person, and measuring against it makes every threshold
look more earned than it is.

`npm run bubble:survival` also reports how many turns are forced, which is the
least obvious thing about this game: on roughly three turns in five the colour in
hand cannot clear anything, so most shots are placements rather than decisions.

## The lab

`/lab/` opens each game in a frame and reaches into it: move any of its constants
and watch the board change, step through levels with the shipped par beside the
one the search finds when asked again, and measure a whole range at once — the
par curve for the two games that have one, the pass rates for the one that does
not.

It is the offline measuring tools with their output on the screen while the knob
is still under the finger. See [docs/design/18-lab.md](docs/design/18-lab.md).

## How a change lands

`main` is protected: it takes pull requests only, and a pull request cannot
merge until both CI jobs pass. That holds for everyone, including the repository
owner, so the way to get something in is the same regardless of who you are.

```bash
git switch -c what-you-are-doing
npm run check          # lint, build, unit tests, size budget, dead code
npm run check:all      # the above plus par verification and the browser suite
gh pr create --fill
```

The two required checks are `lint, unit tests, invariants` and `end to end`. What
each of them is for, and what none of them can tell you, is
[docs/design/14b-ci.md](docs/design/14b-ci.md).

Merging to `main` publishes: the Pages workflow builds from source and deploys,
so what goes live is built from the merge commit.

## Deploying

`npm run build` writes `dist/`, a static folder using only relative paths. Drop
it on GitHub Pages, Netlify, Cloudflare Pages, or any bucket, including a
subdirectory. It is not committed, so build it first.

`dist/decanter-standalone.html` is the same game as a single file, with the fonts
and the one sound inlined. It opens straight off disk but cannot install, since
service workers need HTTPS or localhost.

## Notes

- Levels are deterministic in their number, so level 12 is the same puzzle for
  everyone, and stars mean the same thing on every device.
- Par is the true minimum pour count, not an estimate. It is solved offline and
  shipped as a table, so a slow device and a fast one show the same number. See
  [docs/design/03-par.md](docs/design/03-par.md) for why that is trustworthy.
- Gold is deliberately thin. A vessel costs about three well-played new levels,
  and replaying a cleared one pays stars only, so a stockpile has to be earned on
  new boards. The numbers all live in `CONFIG.economy`.
- Bump nothing to release: the service worker's cache name is a hash of the
  built page, so a new build replaces the old cache on its own.
